`docs/GDD.pdf` 는 최초 원본이다. 변경은 이 문서에 날짜와 이유를 적고, `docs/GDD.md` 의 해당 숫자를 함께 고친다. 원본과 다르면 이 문서가 우선한다.

공 이름 (3.1, 6.4): "[별칭] [종류] +N" 규칙과 구간별 공통 별칭(낡은/쓸만한/빛나는…)을 **폐지**한다. 검 키우기처럼 종류마다 +0~+30 단계 이름이 전부 다르다 (22종 × 31 = 682개, `docs/NAMES.md`, 데이터 `src/core/names.json`). 화면에는 고유 이름과 `+N` 을 함께 보여 준다. 공 외형 장식이 구간(+5, +10 …)마다 늘어나는 규칙(6.4)은 그대로다. 이유: 사용자 결정 ("단계마다 계속해서 간지나게 달라져야 한다").

### 플레이 흐름 변경 (2, 6.1, 6.3) — 팝업 최소화

이유 (사용자 결정): 골/유지마다 "팔기 / 계속 차기" 팝업이 뜨는 게 불편하다. 왼/가/오만 눌러도 계속 진행돼야 한다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 골 · 유지 뒤 | 팔기 / 계속 차기 팝업 | 팝업 없음. "계속 차기" 선택지 자체가 없고 왼/가/오를 누르면 바로 다음 슛 |
| 팔기 | 팝업 안의 버튼 | **화면 오른쪽에 상시 배치**한 버튼. 공이 한 번이라도 골·유지로 살아남은 뒤부터 눌린다. 바닥 방향 버튼과 떨어뜨려 실수 판매를 막는다 |
| 팔기 확인 창 (3장) | 있음 | 폐지. 한 번 누르면 바로 판매하고 판매 결과 연출에서 금액을 처음 공개한다 |
| +1 ~ +13 골 | 팝업 | 팝업 없음. 공 주위에 점점 커지고 화려해지는 이펙트가 터지고 이름이 바뀌는 연출 |
| +14 이상 골 | 팝업 (+15 이상에서 자랑하기) | 팝업이 뜨며 **자랑하기**만 나온다 (닫기 버튼 포함) |
| 자랑하기 기준 단계 | 15 | 14 (설정값 `boastStage`) |
| 유지 · 파괴 알림 | 팝업 / 입력 차단 알림 | 입력을 막지 않는 짧은 토스트 |

### 뽑기 등급 확률 상향 (3.1, 3.4)

- 사용자 결정(2026-10-30): "상위 공의 확률이 너무 낮아서 조금 더 높아도 될 것 같다". 해석: **뽑기에서 나오는 등급 확률**. (고단계 도달 확률을 올리라는 뜻이면 알려 주세요. 그 값은 이번에 건드리지 않았다.)
- 변경: 일반 55 → 45%, 고급 25 → 27%, 희귀 12 → 15%, 영웅 5.5 → 8%, 전설 2 → 4%, 신화 0.5 → 1%. "조금"이라는 말에 맞춰 후보 A 를 골랐다. 후보 비교는 `src/sim/drawrates.ts`.
- 영향 (평균 순이익률, 팔 단계): +7 이 0% → +3%, +10 이 +67% → +76%, +12 가 +133% → +148%, +15 가 +39% → +54%, +17 이 -24% → -9%, +20 이 -107% → -92%. 본전 지점은 여전히 +7 근처이고, +17 이후가 손해라는 설계(GDD 3.4)는 유지된다. 더 올리는 후보 B(40/27/16/10/5/2)부터는 +17 이 이득이 되어 설계가 깨진다.
- 희귀 이상 비율은 20% → 28%, 전설 이상은 2.5% → 5%.
### 공 외형 방식 변경 (6.4, 9장) — 장식 겹치기에서 구간별 본체 재설계로 (**확정, GDD 본문 반영 완료**)

- 사용자 결정(2026-10-30): "+0 은 기본, +5 는 기본에서 약간 변형, +10 은 확실히 멋있게, +15 는 +10 과 비슷하지만 더 화려, +20 이후는 대놓고 과하게. 각 5단계마다 컨셉이 있어야 하고 드라마틱하게 바뀌는 외형을 보고 싶어서라도 더 플레이하게 만드는 것."
- 기존 GDD 6.4 의 "종류별 기본 디자인 위에 단계 구간마다 장식을 겹친다"와 9장의 "기본 이미지 22장 + 티어 장식 7종 겹치기"를 **폐지하고**, 종류마다 구간(+5, +10, +15, +20, +25, +30)별로 공 본체 이미지가 따로 있는 방식으로 바꾼다.
- 구간 규칙과 22종 컨셉은 `docs/BALL_CONCEPTS.md`. 사용자가 용암공 시안을 보고 방식을 승인했고 22종 +5 · +10 · +15 본체를 확정해(2026-10-30) 6.4 와 9장 본문을 고쳤다. 구간이 바뀌는 순간에는 "변신" 연출이 터진다. 에셋 수는 22종 × 7구간 = 154장(현재 +0 22장 확정)이 된다. +20 이상은 크레딧이 생기면 만든다.
- 이전에 만든 "효과만 겹치는" 단계 효과 66장은 이 방향과 다르므로 확정하지 않는다(후보로 보관).
### 구간 변신 연출 (6.2, 6.4)

- 사용자 요구(2026-10-30): "드라마틱하게 바뀌는 외형을 보고 싶어서라도 더 플레이하게 만드는 것." 구간이 바뀌는 골(+5, +10, +15, +20, +25, +30)에서는 공 이미지가 바뀌는 순간을 연출로 보여 준다.
- 순서: 이전 공이 종류 색으로 달아오르며 충전(0~30%) → 하얗게 번쩍하며 교체(30~45%) → 새 본체가 크게 튀어나옴 → 구간 높이에 비례한 충격파 · 불꽃 폭발과 "+N 변신!" 글자 → 안정. 기본 길이 1.5초, "연출 건너뛰기"를 켜면 0.45초. 확률에는 영향이 없다.
- +1~+13 의 일반 골 연출(공 주위 폭발 + 이름 변경)은 그대로이고, 변신 구간만 더 크게 터진다 (변신은 폭발이 1.45배).
- 개발 서버 전용 데모 링크: `#demo=등급_종류번호_단계&win=1` (예: 용암공 +4 → +5 는 `#demo=hero_2_4&win=1`), `&slow=20` 으로 느리게 볼 수 있다. 저장 데이터는 건드리지 않는다.
### 프로토타입 한정: 광고 시청 횟수 제한 해제 (4.1, 5장)

- 사용자 결정: 프로토타입이므로 광고 시청 하루 3회 제한을 잠시 푼다. 설정값 `adDailyLimit` 이 `null` 이면 무제한이다.
- **출시 전에 `adDailyLimit: 3` 으로 되돌린다.** GDD 4.1 · 5장의 원래 값은 하루 3회다. (친구 초대 하루 3명 제한은 서버 단계에서 구현하며 이번 변경과 무관하다.)

### "월드컵 공인구" → "명장면 공" (3.2, 11장)

- 종류 이름을 "명장면 공"으로 바꾼다 (등급 고급, 첫 번째 종류). 가제 규칙(GDD 11장 "출시 전에 가공의 이름으로 바꾼다")은 이 변경으로 해소한다.
- +0~+30 이름은 실제 대회의 유명한 골을 모티브로 하고, 단계가 오를수록 더 유명한 골과 더 큰 수식어(빛나는 → 눈부신 → 불멸의 → 신화로 남은 → 역사를 바꾼 → 종언의)가 붙는다. 사용자 결정 (선택지 1번).
- 쓰는 것: 연도, 대회 단계, 국가, 사건. 쓰지 않는 것: 선수 이름, "월드컵" 표기, 구단 · 리그 이름 (GDD 11장 저작권 · 상표 항목은 이 범위에서 유지). 테스트가 금지어를 검사한다.
- 모든 이름은 `docs/REAL_GOALS_FACTS.md` 에 근거(출처, 확인한 경기 기록)를 적었다. 분 단위가 출처마다 다르거나 확인하지 못한 세부는 이름에서 뺐다.
- 법률 자문이 아니며, 출시 전에 상표 · 초상권 검토가 필요하다.

도감 (6.1): 각 공 종류를 펼치면 최대 도달 단계 이하의 단계별 이름을 볼 수 있다. 아직 도달하지 못한 단계 이름은 보이지 않는다.

영향: GDD 3.4 / 4.1 의 "5,000 골드로 시작" 시뮬레이션 수치는 변경 전 기준이다. 변경 후 수치는 `docs/BALANCE_REPORT.md` 4장에서 확인한다.


### 변신 연출 구간별 강도 (6.4, 9장)

- 사용자 요청: 모든 구간의 변신 연출이 같아 극적임이 부족하다. 높은 강화일수록 번개 · 폭발 등 과할 정도로 화려해야 한다.
- 구성(`src/ui/timing.ts` 의 `SPECS`, 이미지 없이 코드로만 만든다): +5 변신(1.5초, 충전 · 번쩍 · 충격파) / +10 각성(1.9초, 번개 1 · 흔들림 · 폭발 1 · 암전) / +15 폭주(2.4초, 번개 3) / +20 신화 강림(3.0초, 번개 6 · 화면 균열 · 폭발 2) / +25 초월(3.6초, 번개 10 · 색 반전 번쩍) / +30 완전체(4.4초, 번개 16 · 화이트아웃 · 폭발 3 · 색종이).
- 아직 사용자 확정 전의 값이다. 세기와 길이는 확인 후 조정한다.
- 사용자 결정: 변신 연출은 "연출 건너뛰기"와 무관하게 항상 전체를 보여 준다 (구간 도달은 드물고 연출이 1~4초라서).
- 사용자 결정: 배포 준비로 `adDailyLimit` 을 3 으로 되돌렸다 (하루 3회 제한 복구). 위의 "무제한" 항목은 더 이상 유효하지 않다.
